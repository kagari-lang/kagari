# Source-defined language core

**Status: CS01 and CS02 implemented. CS03 owns the remaining protocol groups and iterator migration.** Normal source compilation must provide the language's core traits without installing `kagari-stdlib`. This plan changes who declares those traits, not what their operators mean. The [roadmap](implementation-roadmap.md#source-defined-language-core) tracks this work.

## One example, three owners

Consider `fn same<T: PartialEq>(a: T, b: T) -> bool { a == b }` with an explicit import of `core::cmp::PartialEq`. Before CS02 the checker knew the scalar `==` rule even in an empty environment, but the named trait in the bound required stdlib registration. Comparing two integers alone would therefore be a poor test of this migration.

With authored comparison:

1. `library/core/cmp.kgr` declares `PartialEq` and `Eq: PartialEq` once. A user module can implement `PartialEq` for `Point`; the prelude or a re-export may make the name convenient but does not create the definition.
2. The source frontend supplies core as ordinary package dependencies alongside user source and structured Native inputs. Syntax and HIR resolve `T: PartialEq` to that declaration. The compiler owns the rule that `==` requires `PartialEq`, **not** `Eq`, and independently checks the required role and method shape. The reference in `same` navigates to the authored declaration.
3. Optional stdlib and host modules may reference or implement that trait. A compiled script-only comparison runs without any installed Native module or `.kgr` file. An actual call to a host implementation still requires its matching installed binding. Source text never grants authority to call Rust.

The precedent is [Rust 1.85 `core::cmp`](https://github.com/rust-lang/rust/blob/1.85.0/library/core/src/cmp.rs): library source owns `PartialEq`, the compiler recognizes a language item, and `Eq` is a stronger contract. Reuse this ownership split, not Rust's `Rhs` parameter, borrowed receiver, lifetimes or distribution format. Kagari keeps its own `self`, GC and host boundary.

## Migration inventory

A third party must be able to write a collection library using only core and its own code, without installing or importing `kagari-stdlib`. Core therefore owns both the [26 compiler-recognized protocols](../crates/kagari-types/src/language.rs) listed below and nine ordinary library traits. Only the first group needs language roles. Keep canonical source paths; changing the owning trait of a method or replacing a Native adapter with a Script struct changes definition identity. Rebuild affected products rather than aliasing old identities.

| Source owner under `library/core/` | Language traits to move | Dependencies to account for |
| --- | --- | --- |
| `cmp.kgr` | `PartialEq`, `Eq`, `PartialOrd`, `Ord` | `PartialOrd` returns `Option<Ordering>`; `Ord` returns `Ordering`. Move the required enum declarations with their variant identities. |
| `iter.kgr` | `Iterator`, `Iterable` | `Iterator::next` returns `Option<Self::Item>`; preserve `Iterable::Iter`'s item constraint. Do not depend on a stdlib cursor to test `for`. |
| `ops.kgr` | `Add`, `Sub`, `Mul`, `Div`, `Rem`, `BitAnd`, `BitOr`, `BitXor`, `Shl`, `Shr`, `Neg`, `Not`, `Index`, `Fn`, `Try`, `FromResidual` | Preserve associated outputs and `Try`'s `ControlFlow<Residual, Output>` and `FromResidual` parent. |
| `convert.kgr` | `From` | `Into`, `TryFrom` and `TryInto` are not language roles. Preserve the ordinary conversion blanket impls; do not reinstate compiler reverse forwarding. |
| `fmt.kgr`, `hash.kgr` | `Debug`, `Display`, `Hash` | Scalar/String signature types do not imply installing String methods or host formatting implementations. |

| Source owner | Ordinary core traits to move | What a library author can do without stdlib |
| --- | --- | --- |
| `convert.kgr` | `Into`, `TryFrom`, `TryInto` | Implement `From` or `TryFrom` for a local type and use the reverse direction via core's existing blanket impls. Keep checked `TryFrom` error/result requirements. |
| `str.kgr`, `default.kgr` | `FromStr`, `Default` | Define how a local type parses text or supplies its default value. These contracts require no particular parser or container. |
| `iter.kgr` | `FromIterator`, `Sum`, `Product` | Define how to collect into a local type or aggregate values, independently of any bundled `Vec`. |
| `ops.kgr` | `RangeBounds` | Accept range bounds in a library API using the canonical `Bound` enum. |

`option.kgr` and `result.kgr` own `Option<T>` and `Result<T, E>` and their variants. Core also supplies their `Try`/`FromResidual` implementations and the `ControlFlow`, `Infallible` and conversion dependencies needed for ordinary `?`. Keeping the enum declarations while requiring stdlib for propagation does not meet the boundary. Preserve `Result::Err` diagnostic origin without making arbitrary source enums trusted Native declarations.

Of the [41 foundation traits](spec/builtins.md#foundation-trait-inventory), the six collection interfaces (`List`, `MutableList`, `Map`, `MutableMap`, `Set`, `MutableSet`) remain library-owned. A replacement library need not implement or depend on them. Bundled containers such as `Vec`, `HashMap` and `HashSet` are stdlib products, not prerequisites; their restoration belongs to the existing collections plan. Do not move every optional implementation into core, but no core signature, required body or blanket impl may depend on stdlib. Preserve the full-library surface except for the documented iteration changes below. Do not vary a trait's method list by installation. No role-validator redesign, prelude expansion or new user-facing `no_core` mode is part of this plan.

## Documentation on the authored declarations

Documentation ships with each migrated `library/core/*.kgr` declaration in CS02–CS03; copying its registration summary is not sufficient. Write in English for someone using or implementing the API for the first time. Start from the corresponding **item's** Rust documentation, for example [PartialEq](https://doc.rust-lang.org/1.85.0/core/cmp/trait.PartialEq.html), [Index](https://doc.rust-lang.org/1.85.0/core/ops/trait.Index.html) or [FromIterator](https://doc.rust-lang.org/1.85.0/core/iter/trait.FromIterator.html). Use its questions, examples and level of detail as a model; verify each answer against Kagari's spec and implementation. For Kagari-specific protocols such as `Iterable`, describe the Kagari contract directly.

- **On the trait or type:** lead with what it lets the caller do and when to choose it. Connect it to relevant syntax or a related trait. Separate laws the implementer must uphold from checks the compiler actually performs. For example, `PartialEq` documents `==`; `Eq` explains the extra promise that every value equals itself and why NaN rules out that promise. Do not repeat the comparison tutorial on `eq`.
- **On members and variants:** say what a method returns or changes, what an associated type represents, or what payload a variant carries. Describe defaults, failure results, traps or shared state where observable. For `Index`, explain the key and `Output` in terms of `bag[key]`; it reads an element, not a Rust reference or a writable slot. Do not promise every implementation traps on a missing key.
- **In examples:** use a small Kagari operation and show its outcome. For a trait meant to be implemented, show the distinctive part of an implementation and how a caller uses it. For `From`/`Into`, one example can show both directions: implement `From` once, then call `into` via the blanket impl. Refer back to it rather than duplicating it. Core examples must work without optional stdlib; do not translate Rust examples that rely on `Vec`, moves, lifetimes or Rust-only methods verbatim.

**Review gate:** review the public items, associated members and enum variants with the group that moves them. Check runnable examples against the core-only frontend and execute examples that promise a specific result, reusing existing fixtures where possible. In CS04, verify that tooling shows the authored documentation from a reference to a migrated item, including through a re-export; do not maintain a second copy in a Rust registration or generated view.

## Execution checkpoints

### CS01 — Settle input ownership and the dependency boundary

Trace `PartialEq` from [module registration](../crates/kagari-stdlib/src/foundation/protocols.rs) through [role collection and validation](../crates/kagari-hir/src/language/items.rs), [Native authoring handles](../crates/kagari-stdlib/src/declarations.rs) and the [Engine builder](../crates/kagari/src/engine/builder.rs). Record the exact frontend assembly entry, distribution of the authored files to installed/embedded frontends (no repository checkout or working-directory lookup), and the input to Native module construction **before** `install_all`. Standalone source tooling must not need an Engine or a stdlib dependency.

Close the ownership table at module granularity before moving files. In particular, `core::cmp` is checked for all its roles, and `core::convert` and `core::ops` also contain non-role declarations. Identify required enum/variant facts, current default bodies and Native helpers; distinguish signature dependencies from optional implementations. Assign one owner per canonical module and declaration. Prefer ordinary dependency/re-export and implementation paths, not merging two modules with the same identity. If keeping a public path or a default body requires a new language mechanism or moving optional APIs into core, stop and resolve that tradeoff here first. Specify the name-import policy with and without stdlib; explicit `core::…` must work in both and existing `std` re-exports must keep their identities.

**Exit:** a finite move/retain table, a concrete construction order with no `core → stdlib → core` cycle, and a focused reproduction: an empty Engine accepts scalar equality but lacks the canonical trait for an explicit generic bound. Historical source before `9d083fa89` is a reference, not today's signature inventory.

#### CS01 findings and cutover gate

**Source path verified.** In a fresh default Engine with no providers, compile `fn main() -> bool { 1 == 1 }`: an artifact is emitted. Replace it with `use core::cmp::PartialEq; fn same<T: PartialEq>(a: T, b: T) -> bool { a == b } fn main() -> bool { same(1, 1) }`: the diagnostic is `KG_RESOLVE_UNKNOWN_NAME` on `core::cmp::PartialEq`. Give standalone HIR three ordinary source documents instead: the same application, `kagari-core::option` declaring `Option<T>`, and `kagari-core::cmp` declaring `Ordering` and the four annotated comparison traits. Bind the modules explicitly and give each an import scope mapping `core` to `kagari-core`. `AnalysisSnapshot::check_program` admits all three with no sidecars, Native records or stdlib. This establishes source expressibility, not artifact execution or custom `Point` dispatch.

**Input and construction order.** Package the authored `.kgr` files as resources owned by `library/core/`; the source frontend receives texts, stable URIs and module identities, not Rust-authored signatures. Assemble them with the other source units at [`AnalysisDatabase::prepare_declarations`](../crates/kagari-hir/src/analysis/declarations.rs), not as editable files in an Engine session (package capture replaces the user snapshot). Include the inputs in replay and fingerprints. Add the `core` alias without disturbing project aliases, reject identity conflicts, and keep core independent of the optional `std::prelude`. Preserve installed `std` facades as re-exports.

Prepare checked core first; pass its scoped public trait and enum contracts to Native module authors; only then seal and install actual Native providers. Today [stdlib composition](../crates/kagari-stdlib/src/assembly/composition.rs) starts from an empty catalog, *before* `install_all`. An ordinary source trait reference is not a substitute for this handoff: reserved traits are excluded, and it cannot describe an enum's variants. [Runtime admission](../crates/kagari-runtime/src/native/registry/dependencies.rs) also requires registered contracts for every role of a present language module. Replace that prerequisite with checked source-free evidence, not trust in source names or permission to call Rust. No frontend in the runtime. `cargo test -p kagari --lib constructors_do_not_install_implicit_library_providers` passes. The missing portable `trait_references` observed after the positive Native call are addressed by the CS02 prerequisite below.

Do not introduce a second `String` or silently change shadowing to make core compile. Separate declaration ownership from optional bindings. |

#### Iteration API decision

`Iterable` has one method, `iter(self) -> Self::Iter`; keep its `Item` and `Iter: Iterator<Item = Self::Item>` associated types. `Iterator` owns `next` and the 17 transformation and terminal defaults currently on `Iterable`. Like [Rust's `Iterator::map`](https://doc.rust-lang.org/1.85.0/core/iter/trait.Iterator.html#method.map), `map` wraps the iterator it receives. A container implementing only `Iterable` changes from `bag.map(f)` to `bag.iter().map(f)`. Do not insert an implicit `.iter()` during method lookup or keep forwarding methods on `Iterable`.

`for x in expr` still has **one** entry: evaluate `expr` once, call its `Iterable::iter` once, then call `Iterator::next` until `None`. Every iterator remains iterable via the identity implementation: `it.iter()` returns the same iterator at its current position. No separate loop rule for iterators is needed.

Implement the eight adapters as ordinary `.kgr` iterators in core, without an optional stdlib provider. Preserve lazy evaluation, shared progress, completed effects, and the specified selection of calls and retained callbacks across reload. Validate script-backed storage and calls on those terms; do not keep opaque Native types just to preserve the old representation.

Reentry policy belongs to the concrete iterator, not `Iterator` or the VM. The existing Native adapters explicitly trap on a nested `next()` on the same instance; the new core adapters use ordinary Script calls and do not reject a call solely because it is nested. This is an intentional behavior change, not a promise that every nested call succeeds. Normal traps, cancellation, depth limits and cleanup still apply. Do not add a VM-wide check, duplicate a busy flag across the adapters, or relax unrelated Native borrow and operation guards.

### CS02 — Deliver comparison end to end without stdlib

Supply the first closed group (`core::cmp` and its CS01 dependencies) as authored source, preserving docs and source locations. Give each module its canonical identity once per analysis input set, not once per user file. Use ordinary lowering, imports, signature/body checking and the existing role gates. An application file named `cmp.kgr` is not the core package. Use the checked declarations as inputs to stdlib/host authoring where needed; remove the replaced registration recipes for the group in the same checkpoint. Do not switch between a source definition and a Native definition depending on whether stdlib is installed.

**Prerequisite repaired (ordinary registered traits only).** The importer `demo::counter` registered the exact ABI of `pkg::api::Readable`, but HIR attachment discarded it and compiler ABI collection initialized `trait_references` to empty. Public lookup let the call return `42` without that record; checking the actual owner at runtime did not detect the omission. HIR now retains the adopted importer's expectations separately from local trait definitions, and the compiler emits them even without an impl or call. MIR and bytecode still compare each carried ABI to the reachable owner. Source-free admission additionally compares the importer's complete carried set to its installed set. A stale expectation is never regenerated from the owner's current methods.

**Exit:** in an SDK Engine with no Native providers, compile and execute `same` with a script `Point` whose `eq` compares only one of two fields. Distinct instances equal on that field must compare equal; a different value must compare unequal. The generic bound, impl and navigation all target the authored trait. With stdlib installed, its comparison references resolve to that same identity with no duplicate module. An unrelated same-named trait cannot satisfy the language role.

### CS03 — Move the remaining protocol groups and remove old registrations

Migrate the other inventory rows in dependency order using CS02's route. Preserve declared member order where lowering relies on it, static role/shape checks, ordinary Script defaults, associated type identities and generic implementation selection. Retire each moved Rust declaration recipe and its generated navigation view at cutover, not the checked bindings for real Native implementations. Native-only modules continue to use structured registrations and generated views. Do not create handwritten HIR, a core-specific encoder/decoder, or a Rust table restating the public signatures.

For iteration, update the [HIR role-shape checks](../crates/kagari-hir/src/language/items/shapes.rs), member selection and dependencies on the old method IDs. Keep `iter` and `next` in their respective required slots for [loop lowering](../crates/kagari-compiler/src/source/lower/stmt.rs). Migrate callers, fixtures and docs to the new receiver; do not change the distinct destination traits `FromIterator`, `Sum` and `Product`.

**Exit:** without stdlib, resolve all 35 traits and validate the 26 roles; reject malformed role shapes at their source site or owning declaration. Exercise `Option` early exit, `Result` error propagation and ordinary blanket conversion without installing providers. Reuse a custom `Try` case to guard against hardcoding the two carriers. With stdlib, sample a re-export and a host implementation against the canonical definitions.

The independence test is a small, separate script library, not a second production stdlib: define a collection with its own storage and cursor, implement core `Iterable`/`Iterator` and `FromIterator`, and consume it from a different user module. For the collection `[2, 5]`, check `for x in bag` obtains its iterator once and yields both items. On a fresh `bag.iter().map(|x| x * 2)`, consume `Some(4)` with `next()`, then use `for` on that same iterator: it must yield only `10`, not restart at `4`. Assert the collected values and order without any bundled collection import, registration or helper. This tests library composition rather than merely counting available traits.

### CS04 — Close tooling, packaging and source-free acceptance

Check that normal SDK, CLI and editor analysis use the same core inputs. Navigation lands on the authored declaration and member, including from a stdlib re-export; Native-only navigation remains a projection. Reuse existing snapshot/invalidation boundaries: changing core invalidates dependent checked products, not the meaning of already admitted code. Do not add an independent persistent core cache without evidence.

Run the script comparison artifact in the existing frontend-free consumer with neither core source files nor stdlib registration at execution. Separately sample an actual native call and verify that a missing or mismatched provider fails at the existing admission boundary. Runtime/bytecode must not acquire source, HIR or stdlib dependencies or a `traits.bin` replacement. Keep existing ABI/format identifiers unless separately required; invalidate disposable artifacts if affected. Update [architecture](architecture.md), [builtins](spec/builtins.md) and [declaration inputs/tooling](spec/standard-declarations.md) to describe the implemented ownership. Retire this plan after acceptance; keep outstanding CI in the roadmap.

## Validation and progress

**CS02 implementation.** Six authored modules (`cmp`, `option`, `convert`, `default`, `ops`, `result`) enter ordinary HIR once per input set. An empty SDK executes the script `Point` comparison; optional stdlib uses the same declaration IDs. The source builder exposes checked contracts before installation. A frontend-free builder instead imports ordinary verified bytecode supplied by its host: preparing a declaration catalog never installs a callback. The test-only `core.kbc` fixture is an ordinary compiler output, not a production registry. Packaged inputs use their own parse limits; caller limits still apply to added libraries and user files.

**Execution-side integration.** A Rust callback taking `Option<T>` and returning `Result<U, E>` sealed against verified core, but its signature failed at load: conversion looked for the two enums in the Native registry. Linking now prepares a publication-local conversion catalog after installed-contract admission. It adds only the reached public `Option` and `Result` schemas to the Native type view; their authored origins remain partial evidence, not module providers. Native signature mapping, Host conversion and Serde use the selected publication. Replacing a publication does not mutate an earlier mapping. The stdlib tests compose an explicit verified seed; the standalone trait-table example needs only its own provider. Contract tests no longer depend on stdlib registrations for conversion metadata.

Local samples passed: `scripts/check_features.py --conversions-only` (standalone frontend-free consumer), Cranelift cross-thread native execution, the `host_trait_table` example (Rust callback returns `42`), Runtime authored-contract and dependency admission, stdlib registration, nested Rust/Serde conversions and source-free schema mismatch rejection. An otherwise valid decoded forwarder redirected to a same-signature wrapper fails the qualified-call check, not bytecode update verification. The execution crates' normal dependency trees contain no frontend or packaged source crate. Workspace fmt, all-target Clippy and diff checks passed. No exhaustive test or feature matrix was run.

**Independent failures:** `cargo test -p kagari-stdlib --lib executes_bytecode_foundation_collection_bindings` cannot import `HashMap`/`HashSet`; `standard_documentation_covers_the_registered_api_and_examples_analyze` also references unavailable `Vec`/`HashMap`. The [native collections plan](native-collections-plan.md) owns restoration; the fixtures and assertions remain active. These two collection failures are not comparison or propagation regressions.

The public source-trait ABI test (omitted and stale expectations), private `Marker` importer scope, zero-provider comparison, authored re-export navigation, and session isolation with a zero user nesting budget passed. Both wasm build modes and the standalone AOT host were compile-checked, not executed end to end. Structure, workspace fmt, all-target Clippy, per-file `kg fmt --check` on the six core sources and five new fixtures, and diff checks passed. Full-workspace tests and exhaustive platform/backend/feature coverage remain CI-only.
