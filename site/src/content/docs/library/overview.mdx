Suppose you have a few scores to sort, total and look up by name. You can use the
bundled library for those operations without choosing a package from a registry.
This chapter assumes you can read a function, a collection literal and a `match`;
the <a href={page('start/quickstart')}>quickstart</a> establishes the basic execution
workflow.

## Sort and store an answer

Follow the values rather than the import list:

1. `[22, 20]` constructs a fixed-length array. `Vec::from` creates a separate,
   growable sequence containing those two values.
2. `sort()` changes that vector to `[20, 22]`. The `val` binding still refers to
   the same object; `val` prevents rebinding, not object mutation.
3. `map` builds a lazy iterator. The callback here returns each score unchanged;
   the `for` loop drives it and accumulates `42`.
4. Inserting the total under `"answer"` makes it available through `map.get`.
   A map lookup returns `Option`, so `match` handles both a found value and a
   missing key. The set separately checks whether `42` is present.

The return value is not a printed report. The example's early returns make an
unexpected condition return zero; its successful path returns the stored answer.

## Why some names need no import

A **prelude** is a small set of implicitly available names. `Vec`, `String`,
`Option`, `Result` and their `Some`, `None`, `Ok`, `Err` constructors are examples.
Iteration traits such as `Iterator` and `Iterable`, common comparison/conversion
traits and `Default` are also in the prelude. Local declarations and explicit
imports take precedence over these implicit names.

The prelude is not the entire library. The example explicitly imports `HashMap`
and `HashSet` from `std::collections`. Collection interfaces such as `List` and
`MutableList`, and names such as `Hash`, `Debug`, `Display` and `Ordering`, also
need explicit imports when you name them. An operator can work without its trait
name being imported; writing that trait's bound or implementation requires the
name in scope.

The example also imports the `std::collections` module. That is not a special
switch enabling `map`: transformation methods belong to the ordinary `Iterable`
API, which is already in the prelude.

## Paths are names, not ownership rules

`core` contains foundational types and traits, `alloc` owns `String` and `Vec`,
and `std::collections` contains the collection interfaces and hash containers.
Public `std` paths re-export canonical declarations; for example,
`std::option::Option` and `core::option::Option` name the same type. Choosing a
spelling does not change its implementations or turn a shared object into a
Rust-owned value.

These facilities are installed by the normal Kagari engine and available to the
CLI independently of optional application libraries. Importing a name makes it
visible; it does not install a new Rust service. Host-sensitive operations such
as application IO require explicitly installed host APIs. See the external
<a href={source('docs/spec/standard-declarations.md')}>native library and installation contract</a>
for that boundary.

## Numeric policies and sampling

Numeric methods are installed on the primitive types; no `math` import is needed.
Choose the overflow policy where the algorithm needs it, rather than changing the
meaning of ordinary `+`, `-` or `*`:

- For a fixed-width state recurrence, `state.wrapping_add(increment)` and
  `bits.wrapping_mul(multiplier)` explicitly compute modulo the receiver's width.
  Ordinary arithmetic still traps on overflow in every build.
- For a recoverable range failure, `left.checked_mul(right)` returns `Option`.
  Match `Some(value)` or `None`; this does not suppress unrelated runtime failures.
- `overflowing_add` returns a wrapped value and an arithmetic overflow flag;
  `saturating_add` clamps to the type's range. Neither is an alias for checked `+`.
- `bits.rotate_left(13u32)` uses a `u32` count modulo the receiver's bit width,
  unlike a shift that traps for an out-of-width count. Unsigned
  `wrapping_add_signed` instead takes the corresponding signed-width offset.

Receiver and operands need their exact declared types. For example, a `u64`
wrapping multiply needs a `u64` multiplier, not an implicitly widened `i32`.
Methods evaluate receiver and arguments once, left to right.

The companion <a href={source('examples/numeric-sampling.kgr')}>numeric sampling example</a>
keeps vector/ray calculations and fixed-seed SplitMix64 state in Kagari rather
than installing a native renderer or RNG. SplitMix64's explicit wrapping increment
and multiply steps come from
<a href="https://prng.di.unimi.it/splitmix64.c">Vigna's reference recurrence</a>
(2015 source, consulted 2026-10-21); this is an example algorithm, not a public RNG
API or a cryptographic guarantee. To obtain an `f64` sample in [0, 1), use the high
53 bits scaled by 2^-53. Converting the entire `u64` and dividing by a rounded
maximum can include 1. Keep sample counts bounded and use named, explicitly typed
source-local literal constants; native associated constants are not available.

### Separate exact bits from numerical answers

`sqrt`, rounding, bounds, classification and a finite set of trigonometric,
exponential, logarithmic and power methods are available at both float widths.
`f32` operations stay `f32`. Angles are radians; `y.atan2(x)` takes y as receiver,
while `value.powi(exponent)` takes an exact `i32` exponent even on `f64`.

For a sphere intersection, a negative discriminant's `sqrt()` returns NaN rather
than trapping. Check the domain before using the root in a hit calculation.
`sqrt` is correctly rounded; extended math has unspecified precision, with no
universal ULP bound, portable bit identity or bit-identical repeated approximate
result guarantee. Check analytic numerical results with justified tolerances, not
cross-platform bit snapshots. Power wrappers enforce unit cases even for signaling
NaNs and preserve integer-exponent parity; they are not unconditionally identical
to a direct host Rust power call.

For exact representation work, `f32::from_bits(bits)` takes `u32` and
`f64::from_bits(bits)` takes `u64`. An immediate `.to_bits()` round trip preserves
every bit, including NaN payloads and zero signs. Later arithmetic or math need
not preserve those payloads. `min` and `max` ignore one NaN and may choose either
sign for equal opposite-signed zeros. `clamp` is not a min/max composition:
NaN bounds or reversed bounds cause `ScriptTrap`, even if the receiver is NaN;
valid bounds retain a NaN receiver.

The <a href={source('docs/spec/builtins.md#numeric-scalar-methods')}>numeric inventory</a>
owns the exact signatures, and
<a href={source('docs/spec/value-semantics.md#floating-point-utilities-and-math')}>value semantics</a>
owns edge cases and precision. These calls do not extend native-call const
evaluation or JIT support. A public RNG and full ray tracer are not supplied.

## Find an API without guessing from Rust

Rust-inspired names do not promise Rust's full standard library. Do not assume
that a Rust convenience method, a different container class or an enum combinator
is available. The foundation currently defines **41 traits**, including the
**26 reserved language traits**; the complete
<a href={source('docs/spec/builtins.md#foundation-trait-inventory')}>foundation inventory</a>
and <a href={source('docs/spec/builtins.md#namespaces-and-prelude')}>prelude/path contract</a>
are maintained in one place, rather than repeated as a second API table here.

For current signatures, use those contracts and the
<a href={source('crates/kagari-stdlib/src/foundation')}>installed declaration sources</a>.
The guide focuses on tasks and observable behavior, not a generated API catalog.

`Option`/`Result` control flow, read
