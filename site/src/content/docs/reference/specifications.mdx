Use the guide to learn a task; use a specification to answer an exact behavior
question. **All specification and source links below open the external GitHub
repository on `main`.** They point to tracked owners, not copied website pages or
versioned release API docs. Early-development source and contracts can change
together.

## Start with your question

For example, if `readonly.len()` changes after another alias pushes an element,
the behavior is not an accidental exception to `val`. Read the
<a href={page('library/collections')}>collections walkthrough</a> for the scenario,
then the collection contract below for the precise shallow/live access rule.
Choose the corresponding owner for other questions:

| Question | Authoritative repository reference |
| --- | --- |

| How do generic bounds, associated types and interface values work? | <a href={source('docs/spec/traits.md')}>Traits and interfaces</a> |

These references own the exhaustive signatures, bounds and admissible forms.
This index intentionally does not maintain another trait inventory or repeat a
specification's rules in full.

## Host integration and reload references

For Rust-host work, use the current repository contracts directly:

- <a href={source('docs/spec/embedding-api.md')}>Embedding</a> describes the SDK
  boundary and conversion behavior. It is a semantic API specification, not a
  guarantee that every conceptual name is an exact current Rust identifier.
- <a href={source('docs/spec/standard-declarations.md')}>Native declarations and library modules</a>
  defines explicit installation and registration.
- <a href={source('docs/spec/host-interop.md')}>Host interop</a> and
  <a href={source('docs/spec/typed-path-mutation.md')}>typed path mutation</a>
  own scoped access, declared members and mutation guarantees.
- <a href={source('docs/spec/module-activation.md')}>Loading and activation</a>
  defines checked publication and generation-pinned calls.
- <a href={source('docs/spec/runtime.md')}>Runtime</a> and
  <a href={source('docs/spec/reflection.md')}>reflection</a> describe the execution
  and metadata boundaries.

These are external references, not links to unshipped `host/*` tutorial routes.
For supported versus deferred behavior, consult
<a href={page('reference/status')}>status and limits</a> before treating a design
proposal as an implemented API.

## Artifacts, backends and debugger boundaries

- <a href={source('docs/spec/artifacts.md')}>Artifacts</a> and
  <a href={source('docs/spec/bytecode.md')}>bytecode</a>: executable products and
  validation, rather than a serialized-source shortcut.
- <a href={source('docs/spec/codegen-backend.md')}>Backend contract</a>,
  <a href={source('docs/spec/jit.md')}>JIT</a> and
  <a href={source('docs/spec/aot.md')}>AOT</a>: current native coverage, selection
  and trust requirements.
- <a href={source('docs/spec/debugger.md')}>Debugger</a>: existing hooks and adapter
  boundary, not a promise of an interactive DAP editor session.
- <a href={source('docs/spec/language-conformance.md')}>Language conformance</a>:
  the semantic test organization and contract coverage.
